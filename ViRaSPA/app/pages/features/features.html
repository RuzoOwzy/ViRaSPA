Pages and Routing

  • Page folders — .html, .css, .js and .model.json found by naming convention. Every page on this site is one.
  • History API routing — real addresses, Back/Forward, refresh, bookmarks, case-insensitive matching. Try a page that doesn't exist.
  • No flicker — a page's styles load before it shows; the last click wins.
  • Keep-alive pages — Home keeps its state when you leave and comes back instantly.
  • Plain native pages — a page written in plain HTML, CSS and JS, with no framework calls.
  • Two layouts — this page has layout: "inherit": it keeps the website layout or the app layout, whichever you came from.
  • Focus and scroll — focus moves to each new page's heading; Back restores the scroll position.

Components

  • Three isolation modes — full (Shadow DOM), scoped and none. See them on About.
  • Core components — vs-header, vs-menu, vs-sidebar, vs-user-menu, vs-brand, vs-footer, vs-icon, vs-busy-indicator, vs-toast; they load by themselves when used.
  • Official components — installed one by one from ViRaSPA-Components: vs-card, vs-stat-tile, vs-login-form (Sign In, Dashboard).
  • Icons — self-hosted Font Awesome and Lucide, a character, an SVG file or an image:
  • Native components — plain customElements.define, no framework base class:
  • Extensions — third-party bundles with their own tag prefix, checked for framework version and reserved names.

Session and Privileges

  • Sign in and out — your adapter talks to your backend; the framework stores the session and keeps tabs in step.
  • Private routes — Dashboard asks you to sign in first, then brings you back.
  • Privileges — routes, menus and elements follow them. Users and Settings differ for the two demo accounts.
  • Automatic behaviours you can switch off — sign-out on a 401 answer, expiry, attaching the token.

Busy and Messages

Head Information and SEO

  • Per-page head — title, description, preview image and canonical address change with each page (look at this tab's title).
  • Prerendering — node node-tools/prerender.js writes ready-made copies of public pages for search engines and link previews.
  • Real 404s — servers answer unknown addresses with status 404, from the list of known routes.

Loading and Caching

  • No build step — the files you write are the files the browser runs.
  • Cache strategies — release, custom, auto or revalidate tokens, so browsers never use stale files.
  • Browser check — a clear message instead of a blank page on an old browser or with JavaScript off.

Node Tools

  • serve.js — the development server.
  • install.js — install, pin, restore and verify the framework, components, extensions and libraries.
  • prerender.js — ready-made public pages.
  • deploy.js — copy a release to a server folder safely, with environments and rollback.
  • create-project.js, clean-sample.js, stamp.js — start, tidy and publish.

Every tool explains itself: node node-tools/help.js.
